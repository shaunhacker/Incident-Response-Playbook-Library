# 1. Phishing Incident Response Playbook

## 📌 Overview
This playbook details the step-by-step procedures for investigating, containing, and recovering from phishing security incidents, including malicious email attachments, credential harvesting links, and Business Email Compromise (BEC).

---

##  PHASE 1: Preparation
* **Tooling Requirements:** Mail Gateway (e.g., Proofpoint, M365 Defender), EDR, Sandbox (e.g., Any.Run, VirusTotal), SIEM (Splunk/Sentinel).
* **Pre-requisites:** Ensure SPF, DKIM, and DMARC enforcement policies are active and monitored.
* **Notification Channels:** Dedicated SOC distribution list and user reporting mailbox (`phishing@company.com`).

---

## 🔎 PHASE 2: Detection & Analysis
1. **Initial Triaging:**
   * Extract raw email headers (`.eml` or `.msg` format).
   * Verify sender identity: inspect `From`, `Return-Path`, `Reply-To`, and SPF/DKIM/DMARC authentication results.
2. **Artifact Extraction & Analysis:**
   * **URL Analysis:** Submit suspected links to VirusTotal, URLScan.io, or Hybrid Analysis (do NOT open directly).
   * **Attachment Analysis:** Calculate SHA256 hashes for attached files and detonate in an isolated sandbox.
3. **Scope Assessment:**
   * Query SIEM/Mail Logs to determine how many users received the email:
     ```kql
     // Example Sentinel KQL: Find matching subject lines
     EmailEvents
     | where Subject contains "Suspicious Subject"
     | project RecipientEmailAddress, SenderFromAddress, Subject, Timestamp
     ```
   * Check proxy/DNS logs to identify users who clicked the links or established C2 connections.

---

## 🛡️ PHASE 3: Containment
1. **Mailbox Remediation:** Purge/quarantine the phishing email from all internal user mailboxes globally using Mail Gateway or M365 Compliance Search.
2. **Network Level:** Block malicious URLs/domains and IP addresses at the perimeter firewall and Secure Web Gateway (SWG).
3. **Account Level:**
   * If a user entered credentials on a phishing page: immediately revoke active sessions, reset password, and re-evaluate MFA configurations.

---

## 🧹 PHASE 4: Eradication & Recovery
1. **Host-Level Cleaning:** If an attachment executed malicious code, isolate the host via EDR and initiate a full anti-malware scan or host re-image.
2. **Credential Rotation:** Force-reset passwords across all connected enterprise identity providers (Entra ID / Active Directory).
3. **Restore Operations:** Re-enable cleaned user accounts and restore connectivity after verifying host integrity.

---

## 📝 PHASE 5: Post-Incident Activity
1. **Lessons Learned:** Conduct a post-incident review to analyze MTTR (Mean Time to Respond) and identify security gaps.
2. **Security Awareness:** Inform Security Awareness teams to incorporate real-world samples into future phishing simulations.
3. **Documentation:** Log all extracted IOCs (IPs, domains, hashes) into the Threat Intelligence Platform (TIP).
